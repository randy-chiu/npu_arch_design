# Workload Manifest

## Purpose

`PERF_JOB` records measure jobs; they do not inherently state which model,
layer, or experiment a job belongs to. A report that assigns semantics from
record order becomes unstable as soon as a microbenchmark is inserted or a
regression job is removed.

The v0 workload manifest is the explicit semantic contract between a test run
and its perf/PPA reports. For the C firmware regression it is generated by the
same tool that determines available fixture/model jobs:

```text
sw/tools/firmware/emit_soc_cpu_smoke_data.py
```

For the minimal generated-firmware fallback, `emit_soc_cpu_smoke.py` emits its
matching two-job manifest. `make perf-report` consumes the build artifact at:

```text
build/perf/workload_manifest.json
```

## Schema

The JSON document requires:

```json
{
  "schema": "npu_workload_manifest_v0",
  "manifest_id": "soc_cpu_smoke_v0",
  "run_name": "soc_cpu_smoke",
  "jobs": [
    {
      "job_id": 1,
      "workload": "operator_smoke_matmul",
      "op": "matmul",
      "role": "smoke"
    }
  ]
}
```

`job_id` is the stable join key. The existing SoC testbench uses its
historical one-based job numbering and now emits both canonical `job_id` and
legacy `id`. Optional `tile_id` records a job's position inside tiled
workloads. Optional `workload_metadata` defines one shared `kind` and metadata
object for each workload rather than repeating it for every tile.

## Report Behavior

With `--workload-manifest`, `sw/tools/perf/report.py` requires every observed
`PERF_JOB` to contain `job_id`, checks exact manifest/job membership and
operator agreement, and groups solely by manifest declarations. Missing,
duplicate, unexpected, or operator-mismatched jobs fail with a diagnostic.

Legacy invocation without a manifest remains available temporarily and emits a
warning before using the old order-based inference. It is not suitable for new
baselines.

Generating the manifest next to firmware fixture metadata prevents an enabled
or removed regression path from silently leaving a stale hand-written job
list. PPA proxy reports carry `workload_manifest_id`. Reports with different or
missing manifest identities are marked not directly comparable when either
side declares an identity. This prevents silent changes to workload semantics
from looking like architecture improvements.
